# Redwood Center website

Astro static site in `site/`, published to GitHub Pages on every push to `main`. Most edits are to content data,
not code. Keep changes as small as the request allows, and match the surrounding style.

## Where content lives

- **People**: `site/src/data/people.json`, one object per person.
  - `group` is one of `Faculty`, `Postdocs and research staff`, `Students`, `Staff`, `Alumni`.
  - Current members have `slug`, `name`, `group`, `order`, `title` (e.g. "PhD Student", "Postdoctoral Fellow",
    "Undergraduate"), `affiliation` (department or program), `labs` (e.g. `["Olshausen Lab"]`), `website`, `photo`.
  - Alumni have only `slug`, `name`, `group: "Alumni"`, `order`, `current_affiliation`, and optionally `website`.
    The People page lists alumni by name (linked to `website`), sorted by last name.
  - Moving someone to alumni: set `group` to `Alumni`, add `current_affiliation`, and remove `title`,
    `affiliation`, `labs`, `photo` and `role`. Keep `website` if they have one.
  - `slug` is the name in lowercase with hyphens (`deepthi-bannai`). `order` only matters for Faculty (display
    order); use 999 for everyone else. Other groups are sorted by last name on the page.
  - Photos live in `site/public/media/people/` and are referenced without `site/public/`, e.g.
    `"photo": "media/people/deepthi_bannai_headshot_2025-300x350.jpg"`. They're shown at 300x350, cropped to fill.
- **Seminars**: `site/src/data/seminars.json`, newest first. Fields: `slug` (`firstname-lastname-mon-yyyy`, e.g.
  `jeff-hawkins-nov-2026`), `title`, `speaker`, `affiliation`, `date` (`YYYY-MM-DD`), `time` (e.g. `12:00pm`),
  `location`, `recording_url` (or `null`), `summary` (the full abstract as plain text: paragraphs separated by a
  blank line, links as `[text](url)` or a bare URL or email address). Each seminar gets its own page at
  `seminars/<slug>/`. Upcoming seminars appear on the homepage and at the top of the Seminars page automatically,
  by date.
- **Courses**: `site/src/data/courses.json`, one record per offering (a course in a term), newest first. Fields:
  `slug` (the page is `courses/<slug>/`), `course` (shared by every offering of the same course, e.g.
  `neural-computation`), `code` (e.g. `VS265`, or `null`), `title`, `term` (`Fall 2024`, `Spring 2015`, `Summer
  2018`), `instructors` (list), `url` (only for a course whose page is elsewhere, else `null`), `summary` (one line,
  the page's description for search engines). The page content is plain HTML in `site/src/data/courses/<slug>.html`
  (paragraphs, headings, lists, tables, links; links to site pages start with `/`). The Courses page groups offerings
  by `course` in a table. Lecture files stay on the old server, linked at
  `https://redwood.berkeley.edu/wp-content/uploads/...`. Don't show personal email addresses.
- **Blog posts**: Markdown in `site/src/content/blog/<slug>.md`, with front matter `title`, `date`, `authors`
  (list), `summary`. Use `.mdx` instead for a post that imports components; interactive figures live in
  `site/src/content/blog/widgets/` (no `.md` or `.mdx` files there, or they become posts). Math is `$...$` or
  `$$...$$` (KaTeX); footnotes (`[^label]`) show as margin notes. Plugins for both are in
  `site/src/lib/markdown.mjs`.
- **Research pillars** (Research page and homepage): `site/src/data/research.ts`.
- **Page text**: `site/src/pages/*.astro` (home is `index.astro`); header and footer in `site/src/components/`.
- `site/src/data/news.json` exists but isn't shown on the site.

## Don't hand-edit

- `site/src/data/papers.json`, `papers-map.json`, `filters-*.json` and everything in `papers-db/`: generated by
  the scripts in `scripts/`.
- `.github/`, `package.json`, `package-lock.json`, unless the request is specifically about them.

## Checking a change

`cd site && npm run build` builds the site into `site/dist/`; `npm run dev` serves it at http://localhost:4321.
